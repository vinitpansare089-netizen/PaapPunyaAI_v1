# 🕉️ PaapPunyaAI

### Mythology-Inspired RAG & Multi-Perspective Ethical Reasoning System

> **Ask a question. Consult the Council. Explore different perspectives.**

PaapPunyaAI is an experimental AI system that combines **Retrieval-Augmented Generation (RAG)** with mythology-inspired knowledge to provide contextual ethical guidance from multiple perspectives.

Instead of relying only on an LLM's general knowledge, PaapPunyaAI retrieves relevant stories from a structured mythology knowledge base and uses them as context for reasoning.

The system currently presents perspectives from **Krishna, Shiva, and an Asura**, followed by a **Brahma-based final judgment layer** that aggregates the council's responses.

---

## ✨ What is PaapPunyaAI?

PaapPunyaAI explores the idea of using mythology as a structured knowledge source for AI-assisted ethical reasoning.

A seeker can describe a situation or ask an ethical question.

The system then:

1. Receives the question
2. Generates a semantic representation of the question
3. Retrieves relevant mythology stories
4. Builds a deity-specific reasoning prompt
5. Generates an individual perspective using an LLM
6. Presents multiple perspectives through the Divine Council
7. Passes the council responses to Brahma for a final judgment

The goal is **not to provide absolute moral truth**, but to demonstrate how retrieval, structured knowledge, and multiple AI perspectives can be combined into an interactive reasoning system.

---

## 🏛️ Divine Council

PaapPunyaAI currently uses three distinct perspectives:

### 🪷 Krishna

Focuses on:

* Dharma
* Duty
* Righteous action
* Wisdom
* Detachment from results
* Compassion

### 🔱 Shiva

Focuses on:

* Detachment
* Ego
* Discipline
* Transformation
* Simplicity
* Inner clarity
* Responsibility

### 👹 Asura

Provides a contrasting perspective based on:

* Ambition
* Power
* Desire
* Competition
* Self-interest
* Pride
* Personal gain

The Asura perspective is intentionally different from the other council members rather than automatically producing the same moral conclusion.

### 🕉️ Brahma

Brahma acts as the **final aggregation layer**.

The system passes the individual council judgments to Brahma, which produces a final judgment based on the question and the perspectives generated by the council.

## 🔍 How RAG is Used

The mythology knowledge is stored as structured JSON stories containing information such as:

```json
{
  "id": "shiva_1",
  "deity": "Shiva",
  "title": "Shiva drinks the poison",
  "tags": [
    "sacrifice",
    "compassion",
    "selflessness"
  ],
  "story": "...",
  "teaching": "..."
}
```

When a question is submitted:

```text
Question
   ↓
Embedding
   ↓
Semantic Search
   ↓
Relevant Stories
   ↓
Prompt Construction
   ↓
LLM Response
```

The retrieved stories provide the contextual grounding used by the deity-specific prompts.

## ⚙️ Core Components

### Knowledge Base

Structured mythology stories stored in JSON format.

Current knowledge sources include:

* Krishna stories
* Shiva stories
* Asura stories

### Sentence Transformers

Used to convert questions and mythology stories into vector embeddings for semantic retrieval.

### FAISS

Used as the vector index for efficient similarity search over the embedded mythology knowledge.

### Prompt Engineering

The system constructs different prompts depending on the council member.

The prompts control:

* Deity perspective
* Retrieved context
* Story connection
* Reasoning
* Teaching
* Practical advice
* Karma evaluation

The prompt layer also instructs the model not to fabricate mythology or quotations and to connect its response to retrieved stories.

### LLM Layer

PaapPunyaAI is designed to work with locally available LLMs through **Ollama**.

The project has been tested with local models such as:

* Phi-3
* Mistral

This allows the reasoning pipeline to operate without requiring a hosted LLM API.

### Brahma Aggregation

After the individual perspectives are generated, Brahma receives the council judgments and produces the final judgment.

## 🚀 Running the Project

### 1. Clone the repository

```bash
git clone https://github.com/vinitpansare089-netizen/PaapPunyaAI_v1.git

cd PaapPunyaAI_v1
```

### 2. Start the Docker container

The project includes a Docker configuration based on Python 3.12 with CPU-only PyTorch.

```bash
docker build -t paappunya .
```

Start the development container:

```bash
docker run --rm -it -p 8000:8000 paappunya
```

### 3. Start FastAPI

Inside the container:

```bash
uvicorn main:app --host 0.0.0.0 --port 8000
```

The API will be available at:

```text
http://localhost:8000
```

FastAPI documentation:

```text
http://localhost:8000/docs
```

### 4. Start the frontend

Open another terminal:

```bash
cd frontend
npm install
npm run dev
```

The Vite development server runs on:

```text
http://localhost:5173
```

The frontend communicates with the FastAPI `/ask` endpoint.

## ⚖️ Karma Scoring

Karma scoring is designed as a **future/optional feature of the system**, rather than something that should automatically score every question.

The current prompt logic distinguishes between:

* Asking a question
* Requesting advice
* Describing an actual action or behavior

A score should only be considered when an actual action or behavior is described.

## 🎯 Design Principles

PaapPunyaAI is built around several principles:

### 1. Retrieval Before Generation

Relevant mythology is retrieved before the LLM generates its response.

### 2. Grounded Mythological Context

The model is instructed to use retrieved stories rather than inventing mythology.

### 3. Multiple Perspectives

The system intentionally provides different philosophical perspectives instead of producing a single generic answer.

### 4. Story-Based Reasoning

A response should connect the seeker's situation to a relevant retrieved story.

### 5. Local LLM Experimentation

The project explores running LLM inference locally through Ollama.

### 6. Modular Architecture

Retrieval, embeddings, prompting, LLM interaction, council orchestration, and final judgment are separated into services.
